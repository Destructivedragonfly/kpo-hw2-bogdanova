## 1. Предметная область и DDD

### Ubiquitous Language
Термины предметной области в коде:
- **Student** - студент;
- **AssessmentCriterion** - критерий оценивания с максимальным баллом и весом;
- **Rubric** - набор критериев оценивания;
- **Grade** - оценка студента по конкретному критерию;
- **FinalGrade** - итоговая оценка студента.

### Entities, Value Objects и агрегаты
**Entities:**
- `Student` - студент с уникальным `StudentID`;
- `AssessmentCriterion` - критерий оценивания с уникальным `CriterionID`;
- `Grade` - выставленная оценка с уникальным `GradeID`;
- `Rubric` - набор критериев.

**Value Objects:**
- `StudentID`, `CriterionID`, `GradeID` - типизированные идентификаторы;
- `FinalGrade` - итоговая оценка, определяемая своим значением в процентах, а не идентификатором.

**Границы агрегатов:**
- `Student` - корень отдельного агрегата студента;
- `Rubric` - корень агрегата, который управляет набором `AssessmentCriterion`;
- `Grade` - отдельный агрегат, который хранит идентификаторы студента и критерия, а не сами объекты;
- `FinalGrade` не является самостоятельным агрегатом: он вычисляется на основе текущих оценок и рубрики.

### Invariants
Domain model защищает инварианты:
- ID и имя студента не могут быть пустыми;
- максимальный балл и вес критерия должны быть положительными числами;
- оценка не может быть меньше нуля или превышать максимальный балл критерия;
- оценку можно выставить только по критерию, который есть в рубрике;
- в рубрике не допускаются критерии с одинаковыми названиями;
- для одного студента не может существовать несколько текущих оценок по одному критерию;
- итоговая оценка не задаётся вручную, а вычисляется из оценок студента.

### Ports
Интерфейсы `StudentRepository`, `RubricRepository` и `GradeRepository` находятся в `application/repository_ports.go`.
Они определяют, как приложение работает с данными, но не зависят от конкретного способа хранения. Реализация `JSONFileStore` находится во внешнем слое `adapters`.

### Domain Service
`FinalGradeService` находится в `domain/final_grade.go`.
Расчёт итоговой оценки затрагивает несколько сущностей - `Grade` и `Rubric`, поэтому это правило вынесено в Domain Service.

## 2. Логика расчёта итоговой оценки
Используется взвешенное среднее. Сначала балл по каждому критерию нормализуется относительно его максимального значения, затем учитывается вес критерия.

Формула:

$FinalGrade = Σ((Grade / MaxScore) * Weight) / Σ(Weight) * 100$

В расчёт входят текущие оценки студента. Если оценка по критерию исправляется, старая запись заменяется новой. Итоговая оценка каждый раз вычисляется заново.

## 3. Архитектура
Используется **Clean Architecture (Ports and Adapters)**. Зависимости направлены внутрь.

Структура проекта:
- `domain/` - сущности, бизнес-правила, инварианты, Factory и Domain Service;
- `application/` - ui, `POSFacade` и ports;
- `adapters/` - консольный интерфейс, JSON-хранилище и генератор ID;
- `main.go` - точка входа и настройка зависимостей.

**Направление зависимостей:**

`adapters → application → domain`

**DI:** 

`main.go` - Composition Root создания реализаций зависимостей для `POSFacade`.

## 4. Использованные GoF-паттерны
- **Factory (Creational)** - `GradeFactory` в `domain/grade_factory.go`. Создаёт оценку, проверяя, что критерий входит в рубрику и балл находится в допустимом диапазоне.

- **Facade (Structural)** - `POSFacade` в `application/pos_facade.go`. Даёт консольному интерфейсу единый способ выполнять сценарии приложения, скрывая взаимодействие с несколькими репозиториями и доменными объектами.

- **Strategy (Behavioral)** - `FinalGradeStrategy` и `WeightedAverageStrategy` в `domain/final_grade.go`. Отделяет алгоритм расчёта итоговой оценки от `FinalGradeService`, позволяя заменить способ расчёта без изменения самого сервиса.
